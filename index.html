How it works

From zero to first alert in about five minutes

Install the agent

One package for Node, Python, Go, Ruby and Rust. No sidecar, no config file to babysit.

npm i @beacon/agent

Point it at your services

Beacon auto-discovers routes, jobs and queues, then proposes checks you can accept or edit.

beacon init --env production

Own the on-call rotation

Map services to teams once. Beacon handles escalation, hand-offs and quiet hours after that.

beacon oncall sync --from slack

FAQ

Questions engineers actually ask

How long does setup really take?

Install the agent, run beacon init, accept the discovered checks. Most teams have their first alert configured inside ten minutes, without touching infrastructure.

Does the agent add overhead?

The agent samples asynchronously off the request path. Typical CPU overhead measures under 1%, and you can cap sampling per service.

Can I keep data inside my own network?

Yes. Scrubbing rules run locally before anything is sent, and Enterprise plans support fully self-hosted or VPC-isolated deployments with EU or US residency.

What happens when I exceed my plan?

Nothing breaks. Monitoring keeps running and you get a notice with the overage, billed at the same per-service rate.

Do you integrate with our existing stack?

Slack, PagerDuty, Opsgenie, GitHub, GitLab, Linear, Jira and generic webhooks ship out of the box. Everything is also available through a documented REST API.
